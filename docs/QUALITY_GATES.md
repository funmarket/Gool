# GOOL Quality Gates

This document defines the repository baseline. A command exiting successfully is necessary, but warnings and generated artifacts are also reviewed before the first GitHub push.

## Source boundaries

`npm run architecture:check` enforces the V1 payment rails, API/database layering, centralized Mini App HTTP client, pinned dependencies, and design-cascade restrictions.

Mini App feature pages are route-level lazy imports. MapLibre is loaded only through the map feature rather than global application bootstrap. `scripts/check-miniapp-bundle.mjs` is part of the Mini App production build and enforces separate raw-size budgets: 500 kB for initial JavaScript and 1 MB for any lazy feature chunk. The larger lazy budget acknowledges MapLibre's parse cost without forcing map code into initial startup.

## Clean source gate

Run from the repository root:

```bash
npm run architecture:check
npm run lint
npm run typecheck
npm run test
npm run format:check
npm run build
```

The output must be reviewed. A Vite large-chunk warning is not treated as clean merely because the build exits zero.

## Database gate

With real PostgreSQL URLs configured:

```bash
npm run db:validate
npm run db:migrate -- --name init
npm run db:migration:check
```

The first migration must be generated by Prisma from the checked-in schema. It must not be hand-written to satisfy preflight.

## Security gate

Run:

```bash
npm run security:check
```

High-severity dependency findings block the first push. Update direct dependency pins deliberately, regenerate `package-lock.json` with npm, and rerun all source/build gates. Do not use `npm audit fix --force` as a substitute for reviewing dependency changes.

## Release gate

`npm run deploy:preflight` fails closed when the lockfile or real migration is missing. `npm run release:check` performs a clean `npm ci` followed by the architecture, Prisma, lint, type, test, format, build, migration-status and security gates.
